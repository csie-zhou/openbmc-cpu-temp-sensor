## 1. Prerequisites

| Requirement | Minimum | Check command |
|---|---|---|
| Free disk space | 50 GB | `df -h ~` |
| RAM | 8 GB | `free -h` |
| CPU cores | 4 (more = faster build) | `nproc` |
| OS | Ubuntu 20.04 / 22.04 / 24.04 | `lsb_release -a` |
| Git | Any recent version | `git --version` |
| Python | 3.8+ | `python3 --version` |

> **No Docker needed for QEMU Romulus.**  
> Unlike the RPi4 community fork, the upstream OpenBMC tree builds natively
> on Ubuntu with standard host packages. Docker is optional.

## 2. Day 1 — Clone & Configure

### 1.1 Check disk space

```bash
df -h ~
# Need at least 50 GB free.
# The build directory will grow to ~30–40 GB during compilation.
```

### 1.2 Install dependencies (Ubuntu)

```bash
sudo apt update
sudo apt install -y \
  git python3 python3-pip \
  build-essential chrpath cpio diffstat \
  gawk gcc-multilib iputils-ping \
  liblz4-tool libsdl1.2-dev libssl-dev \
  locales lz4 pylint python3-git \
  python3-jinja2 python3-pexpect \
  python3-subunit socat texinfo unzip \
  wget xterm xz-utils zstd

# Set locale (required by BitBake)
sudo locale-gen en_US.UTF-8
export LANG=en_US.UTF-8
```

> **Note:** If you are on Ubuntu 24.04, also run:
> ```bash
> sudo apt install -y python3-setuptools
> ```

### 1.3 Clone OpenBMC

```bash
# Choose a location with 50 GB+ free — e.g. /home/$USER or an external drive
cd ~
git clone https://github.com/openbmc/openbmc.git
cd openbmc

# Check what you have
git log --oneline -5
```

The top-level directory looks like this:

```
openbmc/
├── meta-ibm/                  ← IBM machine layers (Romulus lives here)
│   └── meta-romulus/          ← Romulus-specific recipes and configs
├── meta-phosphor/             ← Core OpenBMC layer (bmcweb, phosphor daemons)
├── meta-openembedded/         ← Community OE layers (submodule)
├── meta-arm/                  ← ARM BSP layer
├── openbmc-env                ← Build environment init script
└── setup                      ← Convenience wrapper around openbmc-env
```

### 1.4 Explore the repo structure

Before building, spend 15 minutes understanding the layers:

```bash
# See all available machine targets
ls meta-ibm/

# Romulus-specific config
ls meta-ibm/meta-romulus/conf/

# The template config that controls what gets built
cat meta-ibm/meta-romulus/conf/templates/default/local.conf.sample

# bmcweb recipe location (this is what you'll patch later)
find . -name "bmcweb*.bb" -not -path "*/build/*"
# → meta-phosphor/recipes-phosphor/bmcweb/bmcweb_git.bb
# ./meta-phosphor/recipes-phosphor/interfaces/bmcweb_git.bb
```

Key observation: `meta-romulus` is a **machine layer** on top of `meta-phosphor`.
Your `.bbappend` patch will live inside `meta-romulus` so it only applies to
this target.

### 1.5 Initialise the Romulus build environment

```bash
# From the openbmc/ root directory:
. setup romulus build

# What this does:
#   1. Sources the Yocto environment (adds bitbake to PATH)
#   2. Creates the build/ directory with romulus config
#   3. Changes your working directory into build/
```

After running this, your shell is now inside `openbmc/build/`. Verify:

```bash
pwd
# → /home/<you>/openbmc/build

bitbake --version
# → BitBake Build Tool Core version X.X.X
```

> **Important:** Every time you open a new terminal, you must re-source
> the environment before running `bitbake`:
> ```bash
> cd ~/openbmc
> . setup romulus build
> ```

### 1.6 Inspect local.conf

```bash
cat conf/local.conf | grep -v "^#" | grep -v "^$"
```

Key variables you'll see:

| Variable | Value | Meaning |
|---|---|---|
| `MACHINE` | `romulus` | Target hardware (QEMU Romulus emulation) |
| `DISTRO` | `openbmc-phosphor` | OpenBMC distribution |
| `BB_NUMBER_THREADS` | (auto) | How many parallel tasks BitBake runs |
| `PARALLEL_MAKE` | (auto) | How many parallel compiler threads |

```
# My variable
MACHINE ??= "romulus"
DISTRO ?= "openbmc-openpower"
PACKAGE_CLASSES ?= "package_ipk"
SANITY_TESTED_DISTROS:append ?= " *"
EXTRA_IMAGE_FEATURES ?= "allow-root-login"
USER_CLASSES ?= "buildstats"
PATCHRESOLVE = "noop"
BB_DISKMON_DIRS ??= "\
    STOPTASKS,${TMPDIR},1G,100K \
    STOPTASKS,${DL_DIR},1G,100K \
    STOPTASKS,${SSTATE_DIR},1G,100K \
    STOPTASKS,/tmp,100M,100K \
    HALT,${TMPDIR},100M,1K \
    HALT,${DL_DIR},100M,1K \
    HALT,${SSTATE_DIR},100M,1K \
    HALT,/tmp,10M,1K"
CONF_VERSION = "2"
```

You can tune these for your machine:

```bash
# Add to conf/local.conf if the build is too slow or overloads the machine:
echo 'BB_NUMBER_THREADS = "8"'  >> conf/local.conf
echo 'PARALLEL_MAKE = "-j 8"'   >> conf/local.conf
```

Use a value equal to your CPU core count (`nproc`).

## 3. Day 2 — Launch the Build

### 2.1 Start BitBake

```bash
# Make sure you are inside build/ with the environment sourced
# If in a new terminal:
cd ~/openbmc && . setup romulus build

# Launch the full image build
bitbake obmc-phosphor-image
```
I use:
```
env -i HOME=$HOME PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin \
    bash --noprofile --norc -c "
    cd ~/openbmc
    . setup romulus build
    bitbake obmc-phosphor-image
"
```

**Expected build time:**

| Machine spec | Estimated time |
|---|---|
| 4-core, 8 GB RAM | 4–6 hours |
| 8-core, 16 GB RAM | 2–3 hours |
| 16-core, 32 GB RAM | 1–2 hours |

> **Tip:** Start the build first thing in the morning or run it overnight.
> BitBake caches aggressively — subsequent rebuilds of changed recipes
> only take a few minutes.

### 2.2 Monitor progress

Open a second terminal and watch the build:

```bash
# Live BitBake task log
tail -f ~/openbmc/build/bitbake-cookerdaemon.log

# Or watch the build directory grow
watch -n 10 'du -sh ~/openbmc/build/tmp'

# Count completed tasks (rough progress indicator)
grep -c "^NOTE: recipe" ~/openbmc/build/bitbake-cookerdaemon.log
```

A healthy build shows lines like:

```
NOTE: Executing Tasks
NOTE: recipe bmcweb-1.0+git...: task do_compile: Started
NOTE: recipe bmcweb-1.0+git...: task do_compile: Succeeded
```

### 2.3 Locate the output image

When the build finishes:

```bash
ls -lh ~/openbmc/build/tmp/deploy/images/romulus/

# You are looking for:
#   obmc-phosphor-image-romulus.static.mtd
#   obmc-phosphor-image-romulus.static.mtd.gz
```

The `.static.mtd` file is the raw QEMU flash image. It contains the full
OpenBMC system: kernel, rootfs, U-Boot, and all phosphor services including
bmcweb — all packed into a single MTD (NOR flash) layout.

### 2.4 Study while waiting

While BitBake runs, read these files to prepare for Days 3–5:

```bash
# bmcweb's main recipe — understand what it fetches and compiles
cat ~/openbmc/meta-phosphor/recipes-phosphor/bmcweb/bmcweb_git.bb

# Redfish sensor route (the file you will modify later)
# It hasn't been fetched yet; read it on GitHub instead:
# https://github.com/openbmc/bmcweb/blob/master/redfish-core/lib/sensor.hpp

# Romulus machine config
cat ~/openbmc/meta-ibm/meta-romulus/conf/machine/romulus.conf
```

Key thing to note in `bmcweb_git.bb`:

```bash
grep "SRCREV\|SRC_URI\|PV" \
  ~/openbmc/meta-phosphor/recipes-phosphor/bmcweb/bmcweb_git.bb
```

This tells you which **exact commit** of bmcweb is being built. You will
need this later to generate a correct patch.

## 4. Concepts: What You Just Did

### Yocto layer model

```
openbmc/
├── meta-phosphor/       ← Layer 1: OpenBMC core (bmcweb, phosphor-*, ...)
├── meta-ibm/
│   └── meta-romulus/    ← Layer 2: Machine-specific override for Romulus
└── build/
    └── conf/
        └── bblayers.conf  ← Tells BitBake which layers to include
```

Layers are stacked. A recipe in `meta-romulus` overrides the same recipe
in `meta-phosphor`. A `.bbappend` in `meta-romulus` *extends* a recipe from
`meta-phosphor` without replacing it — this is the pattern you will use for
your bmcweb patch.

### What BitBake does

BitBake is the build engine. Given a target like `obmc-phosphor-image`, it:

1. Resolves the full dependency graph (thousands of packages)
2. Downloads source code for each package
3. Cross-compiles everything for the `romulus` ARM target
4. Packs the compiled binaries into a rootfs
5. Assembles the rootfs + kernel + bootloader into a single `.mtd` flash image

The result is exactly what you would flash onto a real AST2500 BMC chip.

### Why Romulus?

Romulus is based on the ASPEED AST2500 SoC — a real BMC chip used in
IBM Power8/Power9 servers and many Lenovo ThinkSystem servers. Building and
running for this target gives you a realistic BMC development experience,
not a hobbyist approximation.

## 5. Troubleshooting

### Build fails with "fetcher failure"

Network issue fetching a source tarball. Retry:

```bash
bitbake obmc-phosphor-image 2>&1 | grep "ERROR\|fetch"
# Identify the failing recipe, then:
bitbake <recipe-name> -c fetch
bitbake obmc-phosphor-image   # resume
```

### "do_rootfs" or "do_image" failure

Usually a disk space issue:

```bash
df -h ~/openbmc/build/tmp
# If low, clear the sstate cache for space:
du -sh ~/openbmc/build/sstate-cache
# You can safely delete sstate-cache — it just slows the next build
rm -rf ~/openbmc/build/sstate-cache
```

### BitBake says "nothing provides X"

Layer not included. Check:

```bash
cat ~/openbmc/build/conf/bblayers.conf
# Verify meta-ibm/meta-romulus is in the BBLAYERS list
```

### "locale" error at start

```bash
export LANG=en_US.UTF-8
export LC_ALL=en_US.UTF-8
```

### Build machine runs out of RAM / OOM kill

```bash
# Reduce parallelism in conf/local.conf:
echo 'BB_NUMBER_THREADS = "4"' >> ~/openbmc/build/conf/local.conf
echo 'PARALLEL_MAKE = "-j 4"'  >> ~/openbmc/build/conf/local.conf
# Then restart the build — BitBake will resume from where it stopped
bitbake obmc-phosphor-image
```
