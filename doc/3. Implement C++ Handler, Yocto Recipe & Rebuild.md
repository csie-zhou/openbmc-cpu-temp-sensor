## 2. Day 6 — Write the C++ Handler

### 2.1 Set up a working copy

Never edit the BitBake work directory directly — it gets wiped on rebuild.
Instead, work in the git repo inside the work directory, generate a patch,
and feed that patch to Yocto.

```bash
# Confirm BMCWEB is set from Day 5
BMCWEB=$(find ~/openbmc/build/tmp/work -path "*/bmcweb/1.0+git/sources/bmcweb*" -maxdepth 6 -type d 2>/dev/null | head -1)
echo "Working in: $BMCWEB"

cd $BMCWEB

# Check git status — should be clean
git status
git log --oneline -3
```

Create a new branch for your changes:

```bash
git checkout -b feature/cpu-temp-sensor
```

### 2.2 Write the handler

Open `redfish-core/lib/sensors.hpp` in your editor:

```bash
# Confirm the line numbers
grep -n "namespace redfish\|namespace sensors\|requestRoutesSensor" \
    redfish-core/lib/sensors.hpp | tail -10
```

The older pattern is adding the code inside the `requestSensorRoutes` function,
just before its closing brace. While the modern pattern **adds a new standalone function pair**.
Here is the complete handler to insert:

```cpp
    // INSERT BEFORE "} // namespace redfish" at line 2537

inline void handleCpuTempGet(
    App& /*app*/, const crow::Request& /*req*/,
    const std::shared_ptr<bmcweb::AsyncResp>& asyncResp,
    const std::string& chassisId)
{
    if (chassisId != "chassis")
    {
        messages::resourceNotFound(asyncResp->res, "Chassis", chassisId);
        return;
    }

    std::ifstream tempFile("/tmp/cpu_temp");
    if (!tempFile.is_open())
    {
        asyncResp->res.result(
            boost::beast::http::status::service_unavailable);
        asyncResp->res.jsonValue["error"]["code"] =
            "Base.1.0.ServiceTemporarilyUnavailable";
        asyncResp->res.jsonValue["error"]["message"] =
            "Thermal sensor not available";
        return;
    }

    int millidegrees = 0;
    tempFile >> millidegrees;
    const double celsius = static_cast<double>(millidegrees) / 1000.0;

    nlohmann::json& j     = asyncResp->res.jsonValue;
    j["@odata.type"]      = "#Sensor.v1_2_0.Sensor";
    j["@odata.id"]        =
        "/redfish/v1/Chassis/chassis/Sensors/temperature/cpu_temp";
    j["Id"]               = "cpu_temp";
    j["Name"]             = "CPU Temperature";
    j["ReadingType"]      = "Temperature";
    j["Reading"]          = celsius;
    j["ReadingUnits"]     = "Cel";
    j["Status"]["Health"] = "OK";
    j["Status"]["State"]  = "Enabled";
}

inline void requestRoutesCpuTemp(App& app)
{
    BMCWEB_ROUTE(app,
                 "/redfish/v1/Chassis/<str>/Sensors/temperature/cpu_temp")
        .privileges(redfish::privileges::getSensor)
        .methods(boost::beast::http::verb::get)(
            std::bind_front(handleCpuTempGet, std::ref(app)));
}
```

Then in `redfish.cpp`, add one line after line 224:
```bash
# Find the location of redfish.cpp
find $BMCWEB -name "redfish.cpp" 2>/dev/null

# Add this
requestRoutesCpuTemp(app);
```

### 2.3 Register the route

Make sure `<fstream>` is included at the top of `sensors.hpp`. Check first:

```bash
grep "#include <fstream>" redfish-core/lib/sensors.hpp
```

If it is not there, add it:

```bash
# Find the include block at the top of the file
head -30 redfish-core/lib/sensors.hpp
```

Then add the include using your editor right after the existing `#include` block:

```cpp
#include <fstream>
```

### 2.4 Generate a patch file

After saving your changes:

```bash
cd $BMCWEB

# Verify the diff looks correct
git diff redfish-core/lib/sensors.hpp

# Stage and commit
git add redfish-core/lib/sensors.hpp redfish-core/src/redfish.cpp
git commit -m "redfish: add cpu_temp sensor endpoint reading sysfs thermal zone

Upstream-Status: Inappropriate [custom sensor for Romulus demo]

Adds a new GET handler at:
  /redfish/v1/Chassis/chassis/Sensors/temperature/cpu_temp

The handler reads /sys/class/thermal/thermal_zone0/temp and returns
a Redfish DSP0268-compliant Sensor resource. Returns HTTP 503 if the
sysfs node is not available."

# Verify both files are in the commit
git show --stat HEAD

# Generate the patch file
git format-patch HEAD~1 -o /tmp/bmcweb-patches/
# → /tmp/bmcweb-patches/0001-redfish-add-cpu_temp-sensor-endpoint-reading-sysfs-t.patch

ls -lh /tmp/bmcweb-patches/
```

> **Important:** Yocto requires an `Upstream-Status` header in every patch
> file. Before copying the patch, open it and add the following line in the
> commit message body, between the `Subject:` line and the `---` separator:
> ```
> Upstream-Status: Inappropriate [custom sensor for Romulus demo]
> ```
> Without this, `bitbake bmcweb` will fail with a QA error during `do_patch`.



Copy the patch to a permanent location in your project:

```bash
mkdir -p ~/openbmc/meta-ibm/meta-romulus/recipes-phosphor/bmcweb/bmcweb/
cp /tmp/bmcweb-patches/0001-redfish-add-cpu_temp-sensor-endpoint-reading-sysfs-t.patch \
   ~/openbmc/meta-ibm/meta-romulus/recipes-phosphor/bmcweb/bmcweb/
```

## 3. Day 7 — Write the Yocto bbappend Recipe

### 3.1 Understand the bbappend pattern

A `.bbappend` file extends an existing recipe without modifying it.
BitBake automatically merges a `.bbappend` with the matching `.bb` recipe
when the machine layer is included.

```
meta-phosphor/
└── recipes-phosphor/bmcweb/
    └── bmcweb_git.bb          ← upstream recipe (DO NOT TOUCH)

meta-ibm/meta-romulus/
└── recipes-phosphor/bmcweb/
    ├── bmcweb_%.bbappend      ← YOUR extension (% matches any version)
    └── bmcweb/
        └── 0001-redfish-add-cpu_temp-sensor-endpoint-reading-sysfs-t.patch
```

The `%` in `bmcweb_%.bbappend` is a wildcard that matches any recipe version
string — `bmcweb_git.bb`, `bmcweb_1.0.bb`, etc. This keeps your bbappend
version-agnostic.

### 3.2 Create the layer directory structure

```bash
# Verify the patch is in place
ls ~/openbmc/meta-ibm/meta-romulus/recipes-phosphor/bmcweb/bmcweb/
# → 0001-redfish-add-cpu_temp-sensor-endpoint-reading-sysfs-t.patch
```

### 3.3 Write the bbappend file

```bash
cat > ~/openbmc/meta-ibm/meta-romulus/recipes-phosphor/bmcweb/bmcweb_%.bbappend << 'EOF'
# bmcweb_%.bbappend
# Extends the upstream bmcweb recipe for the Romulus machine target.
# Adds a custom Redfish sensor endpoint that exposes the SoC CPU temperature
# by reading /sys/class/thermal/thermal_zone0/temp.

# Prepend this recipe's directory to the file search path so BitBake
# finds our patch file in the bmcweb/ subdirectory alongside this file.
FILESEXTRAPATHS:prepend := "${THISDIR}/${PN}:"

# Add our patch to the list of sources BitBake will apply during do_patch.
SRC_URI += "file://0001-redfish-add-cpu_temp-sensor-endpoint-reading-sysfs-t.patch"
EOF
```

Verify it looks correct:

```bash
cat ~/openbmc/meta-ibm/meta-romulus/recipes-phosphor/bmcweb/bmcweb_%.bbappend
```

### 3.4 Verify the recipe is found by BitBake

```bash
# Make sure your environment is sourced
cd ~/openbmc && . setup romulus build

# Ask BitBake to show the resolved recipe for bmcweb
# (it should now mention your bbappend)
bitbake-layers show-appends 2>/dev/null | grep -A5 bmcweb
```

Expected output includes a line like:

```
bmcweb_git.bb:
  .../meta-ibm/meta-romulus/recipes-phosphor/bmcweb/bmcweb_%.bbappend
```

If your bbappend is listed, Yocto has found it.

Also verify the patch file path is resolvable:

```bash
bitbake bmcweb -e 2>/dev/null | grep "SRC_URI"
# Should include your patch filename in the output
# SRC_URI="git://github.com/openbmc/bmcweb.git;branch=master;protocol=https
#          file://run-ptest
#          file://0001-redfish-add-cpu_temp-sensor-endpoint-reading-sysfs-t.patch"
```

### 4.2 Incremental rebuild

```bash
cd ~/openbmc && . setup romulus build

# Clean only bmcweb
bitbake bmcweb -c cleansstate

# Rebuild bmcweb (~5–15 min)
bitbake bmcweb
```

Confirm patch application in the log:

```bash
find ~/openbmc/build/tmp/work -path "*/bmcweb/*/temp/log.do_patch" \
  2>/dev/null | head -1 | xargs tail -20
# Should contain: "Applying patch 0001-redfish-..."
```

Then rebuild the full image:

```bash
bitbake obmc-phosphor-image
# Fast — only bmcweb changed, rootfs repack takes ~2 min
```

### 4.3 Boot the new image

```bash
# Stop current QEMU: Ctrl-A then X
~/openbmc/start_qemu.sh
# Wait ~90 seconds
```

### 4.4 Restart the mock sensor

After every fresh boot, the mock sensor must be restarted inside QEMU
because `/tmp/` is cleared and scripts in `/tmp/` may not persist
across image flashes.

```bash
# Inside QEMU (root@romulus)

# Check if the script survived the flash
ls /tmp/mock_thermal.sh 2>/dev/null || echo "Recreate needed"

# If it exists:
/tmp/mock_thermal.sh &
sleep 3 && cat /tmp/cpu_temp    # confirm it is writing values
```

If the script was lost, recreate it from Day 5, section 4.5, then run it.

## 5. Concepts: Yocto Patch Workflow

### Why not edit the source directly?

The bmcweb source lives inside `build/tmp/work/...` — a directory managed
entirely by BitBake. Any direct edits are wiped by `bitbake -c cleansstate`
or a `do_fetch` re-run. The only safe way to persist changes is through the
recipe layer system.

### The full patch workflow

```
1. Edit source inside build/tmp/work/.../bmcweb/git/
          ↓
2. git commit (inside that git repo)
          ↓
3. git format-patch HEAD~1  →  0001-my-change.patch
          ↓
4. Copy patch to meta-ibm/meta-romulus/recipes-phosphor/bmcweb/bmcweb/
          ↓
5. Write bmcweb_%.bbappend with FILESEXTRAPATHS + SRC_URI += patch
          ↓
6. bitbake bmcweb -c cleansstate && bitbake bmcweb
          ↓
7. BitBake: do_fetch → do_unpack → do_patch (applies your patch) → do_compile
          ↓
8. Your code is compiled into the new bmcweb binary
```

### FILESEXTRAPATHS explained

```bitbake
FILESEXTRAPATHS:prepend := "${THISDIR}/${PN}:"
```

- `${THISDIR}` = the directory containing this `.bbappend` file
- `${PN}` = the package name = `bmcweb`
- So this points to `meta-romulus/recipes-phosphor/bmcweb/bmcweb/`
- BitBake will look in this directory when resolving `file://` URIs in `SRC_URI`
- The `:prepend` and `:` (colon separator) ensure your path is checked first

## 6. Troubleshooting

### Patch fails to apply — "patch does not apply"

The patch was generated against a specific commit of bmcweb. If the upstream
recipe's `SRCREV` points to a different commit, context lines may not match.

```bash
# Check the exact commit your build uses
grep SRCREV ~/openbmc/meta-phosphor/recipes-phosphor/bmcweb/bmcweb_git.bb

# Check the commit in your work directory
cd $BMCWEB && git log --oneline -1

# If they differ, regenerate the patch from the correct base:
cd $BMCWEB
git checkout <SRCREV-from-recipe>     # check out the exact base commit
git checkout -b feature/cpu-temp-sensor
# Re-apply your edits, then:
git add redfish-core/lib/sensor.hpp
git commit -m "redfish: add cpu_temp sensor endpoint reading sysfs thermal zone

Upstream-Status: Inappropriate [custom sensor for Romulus demo]"
git format-patch HEAD~1 -o /tmp/bmcweb-patches/
```

### bbappend not found by BitBake

```bash
# Check that meta-romulus is in bblayers.conf
cat ~/openbmc/build/conf/bblayers.conf | grep romulus

# If missing, add it:
bitbake-layers add-layer ~/openbmc/meta-ibm/meta-romulus
```

### Compilation error: 'fstream' not found

You forgot to add `#include <fstream>`. Check:

```bash
head -30 $BMCWEB/redfish-core/lib/sensors.hpp | grep fstream
```

If missing, add it and regenerate the patch.

### Route not matching — curl returns 404

Check that your `BMCWEB_ROUTE` path has a **trailing slash** or matches
exactly what you curl:

```cpp
// Either register with trailing slash:
BMCWEB_ROUTE(app, "/redfish/v1/Chassis/<str>/Sensors/temperature/cpu_temp/")
// Or without, and curl without trailing slash — they must match exactly
```

### asyncResp->res.jsonValue compile error

Make sure you are using `nlohmann::json& j = asyncResp->res.jsonValue;`
and not trying to assign to `asyncResp->res.jsonValue` as a whole object
(which would overwrite it).
